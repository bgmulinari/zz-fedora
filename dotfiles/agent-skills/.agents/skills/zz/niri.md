# Niri: Config, Keybinds, Window Rules, Displays

Read this before changing anything under `~/.config/niri/`.

```
~/.config/niri/
├── config.kdl        # User-owned entrypoint: includes the product defaults, the DMS
│                     # drop-ins, then local.kdl. Keep it thin.
├── local.kdl         # Personal overrides (optional, loaded last)
└── dms/              # Generated by DMS Settings; do not hand-edit except binds.kdl
    ├── binds.kdl     # Keybinds (user-owned; DMS reads AND writes it)
    ├── colors.kdl    # Theme colors (matugen output)
    ├── layout.kdl    # Gaps, borders, focus ring when overridden in Settings
    ├── outputs.kdl   # Monitors (Settings > Displays)
    ├── input.kdl     # Mouse, touchpad, keyboard (Settings > Input)
    ├── windowrules.kdl, alttab.kdl, cursor.kdl, wpblur.kdl
```

Product defaults live in `~/.zz/dotfiles/niri/.config/niri/defaults.kdl` and its `cfg/`
includes (`layout.kdl`, `rules.kdl`, `input.kdl`, `animation.kdl`, `misc.kdl`,
`autostart.kdl`). Read them to see what a personal override is overriding.

**Commands:** `niri validate`, `niri msg outputs`, `niri msg windows`,
`zz refresh niri/config.kdl`

## Key behaviors

- Niri reloads on config save; still run `niri validate` after every edit and fix
  errors before moving on
- The include order in `config.kdl` decides who wins: product defaults, then `dms/*.kdl`,
  then `local.kdl`. Put personal settings in `local.kdl`, never in `config.kdl` itself
- Colors, border width, and focus-ring width are DMS-owned (`dms/colors.kdl`,
  `dms/layout.kdl`): setting them in `local.kdl` is dead config. Change them in
  DMS Settings instead
- Gaps are the exception: the product baseline lives in `cfg/layout.kdl` and DMS is set
  to defer to it (`niriLayoutGapsOverride = -2`), so gaps go in `local.kdl`
- Input devices (`tap`, `natural-scroll`, numlock, layouts) are DMS-owned through
  `dms/input.kdl` (Settings > Input); only `focus-follows-mouse` and
  `workspace-auto-back-and-forth` are product config
- Reset the entrypoint with `zz refresh niri/config.kdl` (backs up first)

## Keybinds

`~/.config/niri/dms/binds.kdl` is the only file DMS Settings > Keybinds reads or shows,
so keybinds go there, not in `local.kdl`. Format:

```kdl
binds {
    Mod+Return hotkey-overlay-title="Open Terminal" { spawn "ghostty" "+new-window"; }
    Mod+D hotkey-overlay-title="DMS Launcher" { spawn-sh "dms ipc call spotlight toggle"; }
    XF86AudioRaiseVolume allow-when-locked=true { spawn-sh "dms ipc call audio increment 3"; }
}
```

- `Mod` is Super. List current binds with `dms keybinds show niri` or the
  keybind overlay (`dms ipc call keybinds toggle`)
- Niri rejects duplicate binds: when rebinding a key, remove the old line and tell the
  user what it did before
- DMS rewrites the whole file on its first UI edit (drops comments, re-sorts). That is
  expected; the binds survive
- On niri there is no per-bind "reset to default": the supported revert is
  `zz refresh niri/dms/binds.kdl` (whole file, backed up first)

## Window rules

`~/.config/niri/dms/windowrules.kdl` holds the shipped window rules (floating
calculator, audio mixer, screenshot editor, Steam dialogs; blur behind the terminal
and file manager) and is the file DMS Settings > Window Rules reads and edits, so new
rules go there, through the UI or by hand. Every rule needs an id line DMS round-trips:

```kdl
// @id=my-kitty-floating @name=Kitty: open floating
window-rule {
    match app-id="^kitty$"
    open-floating true
}
```

- Find `app-id` and titles with `niri msg windows`; `dms config windowrules list niri`
  shows what DMS sees and where each rule comes from
- Regex backslashes are written doubled inside the quoted string (`"^org\\.gnome\\."`),
  which is how DMS writes them back
- DMS rewrites the whole file on its first UI edit (drops comments, keeps every rule and
  its id line). The supported revert is `zz refresh niri/dms/windowrules.kdl`
- Rules in `local.kdl` still work but are invisible to the Settings UI, and
  `dms/windowrules.kdl` loads later and wins on the same window
- Layer rules and the DMS-generated corner-radius rule are not editable here: the
  former live in the product `cfg/rules.kdl`, the latter comes from Settings > Theme
- Niri's rule syntax is documented in the niri wiki; when unsure, check the version
  with `niri --version` and read the matching wiki page rather than relying on memory

## Displays

Settings > Displays writes `~/.config/niri/dms/outputs.kdl`. Inspect with
`niri msg outputs`; try a mode temporarily with `niri msg output <name> ...`. When
something must beat the DMS-managed configuration, declare the `output` block in
`config.kdl` above the includes; niri uses the first matching output section.

## Layout, animations, misc

Everything in `cfg/layout.kdl`, `cfg/animation.kdl`, and `cfg/misc.kdl` can be
overridden in `local.kdl` with the same node names (gaps, struts, default column
widths, animation speeds, screenshot path, hotkey overlay). Autostart entries from
`cfg/autostart.kdl` cannot be removed by override; ask the user before proposing a
`zz refresh niri/config.kdl` with a hand-maintained entrypoint instead.

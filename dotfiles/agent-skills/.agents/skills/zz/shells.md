# Terminal, Shells, Prompt, Monitors, Editors

Read this before changing Ghostty, Bash or Zsh startup, Starship, btop, fastfetch,
or the seeded editor settings.

## Ghostty

```
~/.config/ghostty/
├── config              # User-owned entrypoint: `config-file = zz-defaults`, then `config-file = ?local`
├── local               # Personal settings (create it)
├── zz-defaults         # Product link into ~/.zz (do not edit)
├── shaders/cursor_tail.glsl   # Product link
└── themes/dankcolors   # Generated by DMS on every theme change (do not edit)
```

Put every personal setting in `local`; it loads last and wins. Ghostty reloads config
with Ctrl+Shift+Comma or in the next window. Keep `theme = dankcolors` unless the user
wants a fixed theme. Shell integration comes from the `ghostty-shell-integration`
package, not from rc files.

## Bash and Zsh

The entrypoints are thin and user-owned; the product defaults load first and personal
fragments last:

| Shell | Entrypoint | Loads | Personal fragments |
|-------|------------|-------|--------------------|
| Bash | `~/.bashrc`, `~/.profile` | `~/.zz/dotfiles/shell/.bashrc` | `~/.shellrc.d/*` |
| Zsh | `~/.zshrc`, `~/.zprofile` (product link) | `~/.zz/dotfiles/zsh/.zshrc` (Oh My Zsh, autosuggestions, syntax highlighting) | `~/.shellrc.d/*` (both shells), `~/.zshrc.d/*` (zsh only) |

Product tool integrations for the selected tools (fzf, zoxide, starship, yazi,
fastfetch) are links under `~/.config/zz-fedora/shell.d/`; each one checks for its
command before enabling anything. Do not edit the links; to disable one, add a
fragment that undoes it, or ask the user before removing the link.

Session environment (PATH order, Wayland and toolkit variables) comes from
`/usr/lib/environment.d/10-zz-desktop.conf`, a ZZ system file. Personal additions go in
`~/.config/environment.d/*.conf`; they need a re-login. Homebrew is deliberately behind
`/usr/bin` in PATH so it never shadows Fedora packages.

## Starship

`~/.config/starship.toml` is user-owned. DMS rewrites only the `[palettes.zz]` block
between its marker comments on every theme change; everything outside is yours. Delete
the markers to keep a fixed palette. Restore the shipped prompt with
`zz refresh starship.toml`.

## btop

`~/.config/btop/btop.conf` is user-owned and selects `color_theme = "dank"`, the
DMS-generated theme at `~/.config/btop/themes/dank.theme`. Pick another theme to stop
following the palette; `zz refresh btop/btop.conf` restores the seed.

## fastfetch

`~/.config/fastfetch/config.jsonc` is user-owned; the ZZ logo it references is a
product link (`~/.config/fastfetch/zz-fedora.txt`). Change modules freely;
`zz refresh fastfetch/config.jsonc` restores the seed.

## Editors

VS Code (`~/.config/Code/User/settings.json`) and Zed (`~/.config/zed/settings.json`)
are seeded once and then user-owned. Their seeded color themes follow DMS
(`Dynamic Base16 DankShell`, `DankShell Dark`/`Light`); everything else is normal
editor configuration. Restore with `zz refresh Code/User/settings.json` or
`zz refresh zed/settings.json`.
